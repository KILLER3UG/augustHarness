# Chapter 1: Introduction

The rise of local AI assistants has reshaped how users interact with intelligent agents embedded in everyday devices and platforms. These models, often trained on curated datasets and fine-tuned for narrow tasks, are designed to perform tool-calling—i.e., invoking external functions or APIs to achieve a goal. However, small language models (SLMs) deployed locally face significant reliability challenges when executing such tool calls. Errors in argument parsing, missing dependencies, or unreliable responses can propagate failures that are difficult to diagnose and recover from.

This project aims to measure the success rate of tool-calling across local AI assistants, identify the dominant failure classes, and evaluate mitigations designed to improve robustness. By systematically logging each invocation, we will classify failures into categories such as malformed input, unavailable tools, or model hallucination. The objective is to quantify how well small models can be made dependable in production-like settings without requiring cloud infrastructure.

In this introduction, I outline the background of local AI assistants and their tool-use mechanisms, articulate the problem of reliability on small models, and state the project's objectives: measuring success, classifying failures, and testing mitigations. The following chapters will present methodology, results, and a discussion of potential solutions.

Local AI assistants are increasingly embedded in smartphones, home devices, and edge servers, where latency and offline operation are critical. While large cloud-based models can offload computation, small local models must operate entirely on-device, relying on lightweight tool-calling primitives such as function invocation, file I/O, or API queries. Because these tools may be unavailable in the user's environment or may return inconsistent results, the reliability of the assistant degrades quickly. For instance, a model might misinterpret an argument schema, fail to discover a required dependency, or generate hallucinated tool responses that lead to incorrect downstream actions. Such failures are hard to trace back to the model itself and often require expensive retraining or cloud fallback.
