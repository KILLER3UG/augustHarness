# Harness study: minimax-code, kilocode, opencode

Method: README + AGENTS.md + docs first, then targeted source reads of agent loop, tools/permissions, memory, skills/plugins, compaction, subagents, providers, update flow, config, error recovery. All claims verified by file reads at the cited repo-relative paths (line numbers where captured). Read-only; no builds/tests/network. Skipped items listed in the Coverage ledger.

---

## 1. minimax-code (MiniMax-AI/minimax-code)

What it is: terminal-first coding agent ("MCode") shipped as TUI, headless `exec`, ACP server, and TS SDK; a closed desktop app is distributed separately. The repo is a reviewed public projection of an internal monorepo (`AGENTS.md` L3, `docs/architecture.md`).

1. **Startup flow** — Installer script or npm installs `mcode`; entry points: interactive TUI `mcode [prompt]`, headless `mcode exec`, ACP `mcode acp`, TS SDK that drives `mcode exec` (README.md L143-148). Session resume via `--continue` / `--session` / `/sessions` (L172-182). Two turn modes fixed at root-session creation: `lightweight` (small system prompt, no tool schemas, no workspace instructions/skills/memory/MCP) and `standard`; child/subagent sessions never inherit lightweight (README.md L150-170).
2. **UI/UX** — TUI with slash commands (`/status`, `/provider`, `/sessions`, `/compact`, `/help`) and shortcuts: `Alt+Enter` queue follow-up mid-task, `Shift+Tab` plan mode, `Alt+M` permission modes, `Esc` interrupt returns the message to the composer (README.md L182-192). Configurable status line (`packages/tui/docs/status-line-config.md`). Desktop app is closed-source; repo only hosts its issues (README.md L299).
3. **Memory** — `LocalMemoryFacade` over a filesystem store with two scopes: `user` and per-`agent`; a main memory file plus a summary. Hard caps: user append ≤500 chars, summary ≤4 KiB, cleanup threshold 64 KiB (`packages/local-memory-facade.ts` L10-13 in `packages/local-runtime/src/memory/`). Memory is exposed as a tool (`local-memory-tool.ts`) and excluded from lightweight mode.
4. **Skills/plugins** — Plugin = directory with `.minimax-plugin/plugin.json` manifest (schemaVersion, name matching dir, category enum, `apps`/`mcpServers`/`skills`/`hooks` with ≥1 non-empty), validated against `schemas/plugins/plugin-v1.schema.json`; the local validator is the same code CI runs (`docs/plugins/README.md` L18-73). Skills: registry + builtin seeds + hub install + an "evolve" config (`packages/local-runtime/src/skills/`: `registry.ts`, `builtin.ts`, `hub-install.ts`, `evolve-api.ts`; `packages/config/src/skill-evolve-config.ts`). Hooks: synchronous command hooks in Claude-compatible format; events include SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, SubagentStart/Stop, PostCompact; hook `systemMessage` is display-only and kept out of model context, compaction input, and exports (`docs/hooks.md`).
5. **Tools + permissions** — Rule model: behavior `allow|deny|ask`; sources `global|agent|session`; modes `default|acceptEdits|bypassPermissions|auto|off`; matchers `tool`, `command` (pattern), `path` (pattern + actions `read|write|delete|execute|network`) (`packages/local-runtime/src/permissions/rule-model.ts` L1-31). Rules persist in a versioned `permission.json` with explicit health failures: `corrupt-json`, `invalid-store-shape`, `unsupported-version`, `invalid-v2-rule` (same file L44-63). Ask-gate + checkers + reply flow in the same dir.
6. **Sandboxing** — Vendored `third_party/sandbox-runtime` "retains the actual sandbox fork, native helpers, and corresponding source" (`docs/architecture.md` L10); config knobs in `packages/config/src/sandbox-config.ts` and `sandbox-settings.ts`.
7. **Context management / compaction** — Dedicated `context-manager` module (`packages/agent-modules/context-manager/src/`: `manager.ts`, `provider-budget.ts`, `output-limit.ts`, `token-estimator.ts`) plus context-usage tracking/calibration (`packages/local-runtime/src/context/`). Tool-result compaction is a first-class configured policy: per-result inline fuse 64 KiB, MCP-details fuse 32 KiB, cumulative watermark 256 KiB, min savings 256 KiB, candidate floor 2 KiB, and `keepRecentRounds: 5` protected rounds (`packages/config/src/tool-result-compaction-config.ts` L3-27).
8. **Subagents** — Task services + `packages/local-runtime/src/agent/` (contract, resource-instance, subagent-telemetry); README advertises "plan tasks, use subagents" (L253). The old `@mavis/team` cycle engine is excluded; TUI delegation uses current runtime task services (`docs/architecture.md` L14).
9. **Model/provider handling** — BYOK: `mcode provider add --base-url … --api-format openai-completions|openai-responses|anthropic-messages`; base URL used as pasted; `--use` connection-tests before saving (failed test saves nothing); optional `--context-limit`/`--output-limit` per model; custom providers live under `custom_provider` in the profile's `config.yaml` (README.md L88-104). Headless model overrides run a read-only account-state check so auth follows the selected model without mutating config (`docs/architecture.md` L22). Catalog/availability in `packages/config/src/minimax-model-catalog.ts`, `model-availability.ts`.
10. **Update mechanism** — Installer scripts into `~/.minimax-code`, npm package `@minimax-ai/code`, source builds as a separate path; no uninstall flag in the installer (README.md L32-58, L196, L259-279). Desktop updates flow through the download page, outside this repo.
11. **Config/settings** — Profile-based data dirs: `~/.minimax` or `~/.minimax-<profile>`, overridable by `MINIMAX_DATA_DIR`/`MAVIS_DATA_DIR` (README.md L85). `packages/config/src/` holds ~40 focused config modules (permissions, sandbox, skills, compaction, TUI, BYOK, telemetry policy…).
12. **Error recovery** — LLM retry + stream timeout hooks in the turn runner (`packages/agent-core/src/pi-turn-runner/llm-retry.ts`, `llm-stream-timeout.ts`); classified termination reasons in `event-bridge/`; a **runaway guard** module with fingerprints, signals, reminder injection, and replay (`packages/agent-modules/runaway-guard/src/`: `guard.ts`, `fingerprint.ts`, `signals.ts`, `reminder.ts`), on by default and remotely overridable (`packages/config/src/runaway-guard-config.ts` L11-19).
13. **Clever / notably bad** — Clever: runaway-guard loop detection; watermark-based tool-result compaction; lightweight mode as a true no-tool strip-down; versioned permission store with health checks; display-only hook notices excluded from model context; `release/public-source.json` inventory making the "public projection" auditable (`AGENTS.md` L14-23). Bad: desktop closed-source; installer lacks an uninstall flag (README.md L196); plugin docs are Chinese while the repo declares English primary (`docs/plugins/README.md` vs README.md L287).

## 2. kilocode (Kilo-Org/kilocode)

What it is: VS Code + JetBrains + CLI coding agent in the Cline/Roo lineage. The CLI engine (`packages/opencode/`) is a fork of upstream OpenCode (README.md FAQ); every product is a client of a `kilo serve` backend over HTTP + SSE via `@kilocode/sdk` (AGENTS.md "Products").

1. **Startup flow** — Extension spawns `kilo serve` as a child process; one `KiloConnectionService` per extension host lazily starts/reuses one backend for sidebar, editor tabs, and Agent Manager; Agent Manager worktree sessions pass a directory context instead of starting a backend per worktree (AGENTS.md). CLI starts from npm/curl/brew/AUR binaries.
2. **UI/UX** — Sidebar chat + Agent Manager multi-session orchestration panel with git worktree isolation (`packages/kilo-vscode/src/agent-manager/`: worktree lifecycle files like `base-branch.ts`, `continue-in-worktree.ts`, `delete-worktree.ts`, `command-budget.ts`). Shared component kit `packages/kilo-ui/src/components/`: collapsible tool blocks (`collapsible.tsx`, `basic-tool.tsx`, `context-tool-results.tsx`), an **auto-approve bar**, diff viewer, error-details panel, agent avatars/colors — tool calls render as status-bearing collapsible cards in the chat stream.
3. **Memory** — Dedicated `packages/kilo-memory/`: file store (`storage/store.ts`), capture operations, recall indexer with token accounting, decisions log, notices. Injection is trigger-based: `explicit | turn-close | rebuild`, producing a budgeted `{text, bytes, estimatedTokens, truncated}` block per project scope, and records injection stats (lastInjectedAt/Bytes/Tokens/SessionID) (`packages/kilo-memory/src/memory.ts` L11-68). A `recall` tool exists in the engine (`packages/opencode/src/tool/recall.ts` + `recall.txt`).
4. **Skills/plugins** — SKILL.md glob discovery (`**/SKILL.md`, `{skill,skills}/**/SKILL.md`) with frontmatter, builtin skills (`src/kilocode/skills/builtin`), trust model (`trustedInProject`), and a remote index.json pull with cache + safe-path validation (`packages/opencode/src/skill/discovery.ts` L14-60; `packages/opencode/src/skill/index.ts` L31-38). Compat: migrates Claude `.claude` / `.agents` skill dirs (`ClaudeMigration`, `CLAUDE_EXTERNAL_DIR`).
5. **Tools + permissions** — Tools in `packages/opencode/src/tool/` (edit, read, write, glob, grep, shell, webfetch, websearch, task, todo, question, plan enter/exit, skill, recall, lsp, diagnostics, apply_patch…), each with a colocated `.txt` prompt-description file. Permissions: ruleset evaluation (`PermissionV1`) with ask/reply; the ask outcome is **explainable** — `AskOutcome { manual, rule }` tells the UI whether a human replied or a rule auto-approved and which rule won (`packages/opencode/src/permission/index.ts` L60-66); approvals can be saved as "always" rules (`saveAlwaysRules` with `approvedAlways`/`deniedAlways`, L68-73); subagent permission narrowing in `agent/subagent-permissions.ts`; Kilo adds ConfigProtection, Headless, drain, ReadPermission, AgentManagerPermission, ExternalDirectoryPermission handlers. `kilo run --auto` auto-approves unless a rule explicitly denies (README.md).
6. **Sandboxing** — `packages/kilo-sandbox/` plus a `packages/containers/` package (not read in depth — see ledger).
7. **Context management / compaction** — `packages/opencode/src/session/compaction.ts` L38-44: prune below 20k tokens, protect 40k, tool output truncated to 2 000 chars, the `skill` tool is prune-protected, and 2k-15k recent tokens are preserved verbatim. Kilo adds `KiloCompactionPayloadRecovery` and `KiloCompactionChunks` for robustness of in-flight compaction.
8. **Subagents** — Agent schema with `mode: subagent|primary|all`, per-agent permission ruleset, optional model override, temperature/topP, `steps` limit (`packages/opencode/src/agent/agent.ts` L32-58). Built-in prompts: ask, debug, explore, orchestrator, summary, title, compaction (`agent/prompt/`) plus Kilo scout (`kilocode/agent/scout.txt`). Agents can be **generated** from a description (`generate.txt`). `task` tool spawns subagents.
9. **Model/provider handling** — `kilo-gateway` package (provider registry, auth, usage, FIM autocomplete) behind 500+ models with mid-task switching at provider pricing (README.md); engine side: `packages/opencode/src/provider/` (`models.ts`, `model-cache.ts`, `transform.ts`, `model-status.ts`).
10. **Update mechanism** — VS Code/JetBrains marketplace auto-update + CLI installers; release processes in `RELEASING.md` and `packages/kilo-jetbrains/RELEASING.md` (not read in depth).
11. **Config/settings** — `ConfigV1` schema; experimental flags follow Kilo's own settings section, not VS Code's (AGENTS.md); Claude config migration; fork guard scripts (`check-kilocode-change`, `check-opencode-annotations.ts`, `check-workflows.ts`).
12. **Error recovery** — `session/retry.ts`, `message-error.ts`, `to-session-error.ts`; compaction payload recovery; worktree discard/delete paths in Agent Manager.
13. **Clever / notably bad** — Clever: the fork-discipline system — every Kilo change in shared upstream files is annotated `kilocode_change`, CI enforces it, with exempt paths (`src/kilocode/`) — a workable recipe for tracking a fast-moving upstream; explainable permission outcomes; colocated per-tool prompt text; worktree-isolated multi-session UI sharing one backend. Bad: double architecture tax (kilo-* packages wrapped around a forked core with marker archaeology); root `bun test` intentionally fails ("do not run tests from root", AGENTS.md) — a workflow footgun; `main` frozen for features (README.md L1-3).

## 3. opencode (sst/opencode)

What it is: the upstream open-source coding agent Kilo forks. Effect-TS service architecture; packages for TUI, desktop (Electron), server, SDK, plugins; a Cloudflare update service under `services/update/`.

1. **Startup flow** — CLI installs (npm/brew/pacman/nix/mise/curl); `opencode service status` discovers an elected background server and injects its local credential for dev work (`AGENTS.md` Live TUI Testing). Desktop app (Electron, beta) spawns the CLI as a managed sidecar (`packages/desktop/src/main/service/`: `background-service-machine.ts`, `cli-stages.ts`, `cli-version.ts`, `sidecar-credentials.ts`, `sidecar-probe.ts`).
2. **UI/UX** — TUI built from feature-plugins (`packages/tui/src/feature-plugins/`: home, prompt, sidebar, system). Desktop: main/preload/renderer with IPC handlers composed in `src/main/ipc.ts`, renderer reaches main only through `window.electron` + MessagePort RPC; lifecycle is a state machine (`src/main/lifecycle/machine.ts`); sqlite preferred for desktop persistence; strict i18n governance (never hardcode English strings; verified terminology via CLDR/Mozilla corpora); design tokens by semantic role (no raw hues); a dot-matrix `Spinner` is reserved for AI activity while everything else uses `Loader` (`packages/desktop/AGENTS.md`).
3. **Memory** — No dedicated long-term memory module found in core (session history, instructions, and compaction only); Kilo adds memory as a downstream package. Treat as a gap/opportunity, verified by absence in `packages/core/src/` listing.
4. **Skills/plugins** — `packages/core/src/skill/` (discovery + instructions); plugin system across `packages/plugin`, `packages/plugins`, `packages/gui-plugins`, `packages/plugin-browser`, and core `plugin.ts` with hooks that can settle permission requests (`PluginHooks` imported in `packages/core/src/permission.ts` L16).
5. **Tools + permissions** — Tool registry with schema-first definitions (`Tool.Info` with input/output JSON schema); the runtime enforces the declared `Tool.Error` contract at the untrusted boundary so a plugin's foreign failure cannot slip past typed handlers (`packages/core/src/tool/runtime.ts` L33-52). Permissions: wildcard rulesets with a **default-deny** baseline for agents without rules — `missingAgentPermissions = [{ action: "*", resource: "*", effect: "deny" }]` (`packages/core/src/permission.ts` L21); org-level managed policies with denial messages, last-match-wins (`packages/core/src/managed-policy.ts` L4-33); persisted decisions (`permission/saved.ts`).
6. **Sandboxing** — Worktree isolation (`worktree.ts`), persistent PTYs, shell services; no dedicated sandbox package in core (Kilo's kilo-sandbox is the downstream answer).
7. **Context management / compaction** — Compaction settings are explicit policy: `{ auto, buffer (keep ~15%, min 16k free; share strings like "20%"), keep (recent tokens verbatim), precompute }` — summaries are **precomputed in the background as context nears the threshold and swapped in** (`packages/core/src/session/compaction.ts` L47-56). Overflow detection via `isContextOverflowFailure`; recent-text tracking (`session/recent-text.ts`).
8. **Subagents** — Subagent runs are background **jobs with recovery records**: `recovery: { kind: "subagent", childSessionID }`; only an explicit caller cancel releases the child's claim — a server shutdown interrupts the job but leaves the child resumable (`packages/core/src/session/subagent-job.ts` L20-40); completion wiring in `session/subagent-completion.ts`.
9. **Model/provider handling** — `model-resolver.ts`, `model-retry.ts`, `models-dev.ts` (models.dev catalog), OAuth + credential services, usage-limits against the Console workspace (`usage-limits.ts`), AI SDK adapters in `packages/ai`.
10. **Update mechanism** — A Cloudflare Worker serves per-channel feeds with **gradual rollout**: eligibility from publication time + SHA-256 of channel+IP, so each IP keeps its rollout position across releases; minimum-release bypass; fallback to newest eligible prior artifact; desktop electron-updater manifests (`latest-mac.yml`, `latest.yml`, `latest-linux*.yml`) with SHA-512 checksums (`services/update/README.md`).
11. **Config/settings** — Schema-first config in `packages/schema`; config documents can carry integration policies; flags service (`flag.ts`); location-scoped services.
12. **Error recovery** — Runner retry layers (`session/runner/retry.ts`), typed session errors (`to-session-error.ts`), job recovery kinds, IPC machines with tests, sidecar probes for the desktop CLI.
13. **Clever / notably bad** — Clever: staged update rollout with minimum-version floors; desktop-as-sidecar pattern (version-checked CLI + credential injection); background-precomputed compaction; default-deny permission baseline; reserved AI-activity spinner; fixture-driven TUI storybook via `OPENCODE_STORY` (AGENTS.md). Bad: heavy Effect indirection (Location/LayerNode/AppNodeBuilder) taxes the hot path and onboarding; ~35 packages for one product; install tip "Remove versions older than 0.1.x before installing" (README.md) signals upgrade friction.

## Ideas worth stealing for August

1. **Tool-result compaction policy with watermarks** — minimax-code `packages/config/src/tool-result-compaction-config.ts` (per-result fuse, cumulative watermark, min savings, protected recent rounds). Fits August's budgeted tool loop: add a compaction pass over old tool results in `backend-py` turn loop instead of only truncating single outputs.
2. **Runaway-guard loop detection** — minimax-code `packages/agent-modules/runaway-guard/src/` (fingerprints + signals + injected reminder). Cheap to port as a backend-py loop watcher that nudges the model before burning budget; complements `update_state` progress tracking.
3. **Explainable permission decisions** — kilocode `packages/opencode/src/permission/index.ts` `AskOutcome { manual, rule }` + saved "always" rules. August's 4-level guard modes should surface *why* something auto-ran (which rule/level) in the desktop UI, and let one approval persist as a scoped rule.
4. **Permission store as versioned JSON with health checks** — minimax-code `rule-model.ts` (matchers tool/command/path × actions, corrupt/unsupported-version errors). A concrete shape for August's guard-rule persistence in `backend-py`.
5. **Precomputed compaction** — opencode `packages/core/src/session/compaction.ts` Settings (`buffer`, `keep`, `precompute`): summarize in the background near the threshold and swap in. Fits August's local, budgeted context management without blocking a turn.
6. **Desktop sidecar with version handshake** — opencode `packages/desktop/src/main/service/` (background-service machine, cli-version, sidecar-credentials). Directly maps to August's Tauri shell + bundled FastAPI backend: check backend version on boot, probe readiness, inject local credentials.
7. **Staged update rollout + minimum version floor** — opencode `services/update/README.md`. August's silent in-place update could adopt a minimum-version floor and staged availability even in a simple feed, plus SHA-512 manifests.
8. **Colocated per-tool prompt text** — kilocode `packages/opencode/src/tool/*.txt` beside each tool. Keeps tool descriptions versioned with code; August's backend-py tools + Anthropic/OpenAI tool surfaces could generate descriptions from one colocated source, keeping the two surfaces in sync by construction.
9. **Memory injection with token accounting and triggers** — kilocode `packages/kilo-memory/src/memory.ts` (`explicit | turn-close | rebuild`, budgeted block, injection stats). Extends August's markdown-fact memory: a budgeted recall block per turn with recorded injection sizes, without adding a second store.
10. **Plugin/skill manifest schema + local validator mirroring CI** — minimax-code `docs/plugins/README.md` + `schemas/plugins/`. August's `.aug/skills` discovery could adopt a manifest schema and a `validate` gate so bad skills fail fast, with the same trust class as repo AGENTS.md.
11. **Lightweight no-tool mode** — minimax-code README.md L150-170: cheap chat mode omitting tool schemas, skills, memory. Fits August for Q&A turns that shouldn't pay the tool-loop tax.
12. **Reserved AI-activity indicator + semantic design tokens** — opencode `packages/desktop/AGENTS.md` (Spinner only for AI activity; tokens by semantic role). Small, high-signal UX rules for August's Claude-Desktop-style chat UI.

## Anti-patterns to avoid

- **Forking without annotation discipline** (kilocode): without `kilocode_change` markers + CI checks + exempt paths, a fork of a fast-moving upstream becomes unmergeable. If August ever forks a component, adopt marker + check from day one.
- **Two permission/tool systems drifting** (kilocode re-exports upstream PermissionV1 while adding parallel Kilo handlers; minimax-code keeps Anthropic/OpenAI tool lists in sync by rule). August already mandates sync between its two tool surfaces — automate it rather than relying on discipline.
- **Over-abstracted hot path** (opencode's Effect Location/LayerNode graph): powerful, but a small product pays in debuggability and onboarding. Keep August's FastAPI request path plain.
- **Installer without a symmetric uninstall path** (minimax-code README.md L196) and upgrade friction ("remove versions older than 0.1.x", opencode README.md). August's install/update story should include clean removal and stale-tree rules (already a non-negotiable).
- **Display/context channel mixing** — minimax-code had to explicitly keep hook `systemMessage` out of model context, compaction, and exports (`docs/hooks.md`); decoration that leaks into model context becomes prompt noise. Keep August's UI-only notices out of the transcript.
- **Closed-core projection** (minimax-code desktop): shipping a partial public projection limits community fixes and complicates provenance; August is fully local — keep all product code inspectable.

## Not applicable to August (and why)

- **Managed cloud services**: MiniMax OAuth/lease broker, Kilo gateway/console/marketplace, opencode Console usage limits — August is local-first with user-pasted provider base URLs.
- **IDE extension hosts** (kilo-vscode/KiloConnectionService, kilo-jetbrains): August's shell is Tauri, not an editor extension; only the *patterns* (shared backend, worktree sessions) transfer.
- **Cloudflare Worker update infra as code**: concept transfers (rollout, minimum floor), the deployment does not fit a local-first product.
- **Vendored engine internals** (minimax-code `third_party/pi-mono`): noted as the agent engine; not studied line-by-line.
