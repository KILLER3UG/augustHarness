Method: static read-only pass. pi: README, coding-agent docs (how-pi-works, compaction, extensions, skills, settings, usage, containerization, packages, codemode, cli), agent-loop.ts, edit.ts, truncate.ts, file-mutation-queue.ts, compaction.ts, read.ts. omp: README, docs (memory, compaction, ttsr-injection-lifecycle, tools/task, tools/edit, tools/read, advisor-watchdog, lsp-config, mnemosyne-memory-backend), source-tree survey (crates/, packages/coding-agent/src/). Skipped: full source of pi-tui/pi-ai, omp collab-web/browser-relay/python, bazel config, benchmarks, most tool docs.

## Part 1 — pi (earendil-works/pi)

Design stance: "minimal, extensible agent harness". Core stays small; almost everything is an extension point. README.md states the loop is: query LLM → parse tool calls → execute in parallel → append results → repeat until done; no turn bound — it trusts the model + context window.

1. **Startup flow** — `pi` (CLI) or `pi-ai`/`agent` as library. Config load (~/.pi/agent/settings.json + project .pi/settings.json) → project-trust resolution (`docs/extensions.md`: project_trust fires before project resources load) → extension discovery (~/.pi/agent/extensions, npm/git packages via `pi install`, project .pi/extensions after trust) → session start → `resources_discover`/`resources_loaded`. Startup failure of a package warns + skips, retries next start (docs/packages.md:19).
2. **UI/UX** — pi-tui: differential-render terminal UI, fullscreen default. Tool calls render as expandable blocks (Ctrl+O), footer shows model/context/cost. Editor features: @file search, `!` bash passthrough (docs/usage.md:68-76), autocomplete, themes, keybindings (docs/keybindings.md). Steering (queued user msg) vs follow-up (interrupt + run) are first-class loop states (docs/usage.md:33-40).
3. **Memory model** — none persistent. Sessions are JSONL trees (branch/fork/clone); compaction summaries + skills are the only cross-session state. No vector store, no memory backend.
4. **Skills/plugins/extensions** — Extensions: TS modules loaded in-process via jiti; ~30 lifecycle events; can register tools/commands/providers/UI; can block tool execution (docs/extensions.md:983-1013 tool_call contract; parallel tool mode notes 792-812). Skills: SKILL.md dirs, Agent Skills spec (docs/skills.md). Themes, prompt templates, model catalogs are all resources. Distribution: `pi install npm:|git:|./local` (docs/packages.md:12-14).
5. **Tool + permission model** — 8 built-ins: read, bash, powershell, edit, write, grep, find, ls. **No permission system by design** — runs with user's permissions; sandboxing is delegated to containers (docs/usage.md:107-108, README.md:88-97). Extensions may veto via tool_call. `defaultTools` / per-tool settings; codemode compresses the tool surface into a scripted meta-tool (docs/codemode.md:3,50-52).
6. **Sandboxing** — none built-in. docs/containerization.md:9-14: Docker, Gondolin micro-VM, OpenShell patterns; network flags; docker-compose for MCP servers.
7. **Context management** — auto-compaction at model threshold minus reserveTokens (16384) with keepRecentTokens (20000) (docs/compaction.md:419-437); cut only at user-message boundaries, never inside a tool batch; split-span = two summaries around a preserved middle; per-model overrides (439-462). serializeConversation truncates old tool results to 2000 chars, drops thinking (compaction.md:291). Overflow → compact-and-retry (agent-loop overflow handling). Branch summaries on session-tree navigation. System prompt patched via toolsAdded/toolsRemoved deltas (agent-loop.ts:342-372) to preserve provider prompt cache. Prompt-cache warming (idle + streaming) with cost estimates (docs/settings.md:21).
8. **Subagent design** — explicitly out of core (README.md:52-54 "skips features like sub-agents and plan mode"); build-your-own via extensions.
9. **Model/provider** — pi-ai unified client: anthropic/openai/google/+; models.json catalog; OAuth; thinking levels off..max; virtual models; custom providers via registerProvider; catalog refresh from pi.dev.
10. **Update** — `pi update` + self-update command (docs/cli.md:273-301); npm/git based; **supply-chain hardening**: install-lock pinned deps, `npm install --ignore-scripts`, `minimumReleaseAge: 2d`, CI audits (README.md:168-181).
11. **Config** — layered JSON: ~/.pi/agent/settings.json ⊕ project .pi/settings.json (recursive merge, project wins, arrays replaced); JSON-schema validated; env-var reference (docs/environment-variables.md).
12. **Error recovery** — agent-level retry w/ exponential backoff (3 attempts, docs/settings.md:128-136); provider retries off by default (maxRetries 0) — August-compatible stance; length-stop → **failToolCallsFromTruncatedMessage**: every tool call in a truncated assistant msg is marked failed (agent-loop.ts:488-513); abort returns queued messages to the editor; compaction-retry on overflow; crash-log/bug-report tooling.
13. **Clever / notably bad** — Clever: declareToolChanges cache-preserving tool-loadout deltas; failToolCallsFromTruncatedMessage; per-realpath file-mutation-queue (file-mutation-queue.ts — serializes same-file writes across parallel tool calls); BOM/CRLF normalization in edit (edit.ts:185-201); prepareArguments quirk-shimming for models that stringify edit args (edit.ts:98-129); session trees with labels + branch summaries; compaction summary carries firstKeptEntryId + cumulative file-op tracking (compaction.ts:60-114). Bad: zero permission story (trust-the-user stance), extensions run in-process with full user privileges (supply-chain mitigations are process-level only), no subagents/tasks at all.

## Part 2 — oh-my-pi (can1357/oh-my-pi)

Fork of pi that kept the harness skeleton and layered a large optimized stack: TS packages + ~80k-line Rust core (crates/pi-*, README.md:31,466-504), Bun runtime, N-API natives (grep/shell/image/text — no fork/exec), bazel build.

1. **Startup** — pi's flow + discovery sweep of foreign configs (.claude/.cursor/.windsurf/.gemini/.codex/.cline/.github/copilot/.vscode → rules/skills/agents/MCP, README.md:577-579), LSP server auto-detection from rootMarkers + binaries (docs/lsp-config.md:9-13), memory-backend init (doc `memory.md`), advisor roster (WATCHDOG.yml), EditStore snapshot DB (edit/store.ts).
2. **UI/UX** — pi-tui derivative + tool "cards", streaming edit previews, mid-turn **ask tool** (HTML form w/ preselected recommendation), Agent Hub (Alt+A) roster for parked subagents, inline images/sixel, collab QR session links, magic keywords (ultrathink/chillax/orchestrate/workflowz alter reasoning budgets/subagent behavior, README.md:321-330).
3. **Memory** — 5 backends: off | local | hindsight | mnemopi | sharpshooter (docs/memory.md:5-11). Local = two-phase pipeline: per-session extraction → consolidation into MEMORY.md + memory_summary.md + skills/ (76-88); recall injected as *background* at first turn and persisted in-session so the prompt cache stays stable; memory:// read protocol; retain/learn/recall/reflect/memory_edit tools; secret redaction; lease/heartbeat coordination for concurrent startups. mnemopi: local SQLite w/ embeddings+FTS+graph (doc mnemosyne-memory-backend.md). hindsight: cloud outbox model (154). sharpshooter: Obsidian-style markdown vault (160-182).
4. **Skills/plugins** — pi's system + rulebook rules (TTSR), .omp/agents agent defs, hooks, slash commands, marketplace, and **imports from 8 foreign formats** (Cursor MDC, Cline, Codex AGENTS.md, Copilot applyTo, …).
5. **Tools + permissions** — 31 built-ins (README.md:269-317): adds task, ask, wait, apply_patch, lsp_*, dap_*, browser_*, computer_*, tts, todo, session ops, memory ops… Approval modes doc (docs/approval-mode.md), plan mode = read-only tool profile, per-scheme read/exec approval tiers (URL/internal-resource), ACP request_permission bridge, TTSR rules can veto.
6. **Sandboxing** — bash sandbox via pi-iso crate: APFS clones, btrfs/zfs reflinks, overlayfs, projfs, rcopy; task isolation captures patch/branch for merge-back; ovnfs copy-on-write checkouts; native Windows (no WSL).
7. **Context management** — the deepest divergence. Method order [remote, snapcompact, handoff, shake, soft] with per-method settings (docs/compaction.md:531-554); **speculative/async compaction** starts in the pre-threshold band so the commit is instant (532, 70-79); **idle compaction timed to prompt-cache TTL** (545-547); **superseded-read pruning** — old read results blanked when a newer read of the same file exists, cache-aware (read-supersede.ts, compaction.md:548); **useless-result elision** — blank tool outputs that changed nothing (dropUseless, 259-267); pre-compaction prune protects 40k recent tokens, needs ≥20k savings, 50-token floor (246-257); snapcompact = bitmap "imaging" of context for lossless-ish reexpand (221-232); provider-native compaction endpoints (OpenAI /responses/compact V2, Anthropic beta, Bedrock) (341-354); display transcript keeps full scrollback (238-240); experimental notes-backed windows (167-207). Failure of a method falls through to the next in order.
8. **Subagents** — `task` tool with batch shape `{context, tasks[]}`, per-item agent type/model/outputSchema/effort/isolated (docs/tools/task.md:37-47); worker threads with W(n) placement (150-157); speculative launch mid-stream; semaphore 32; idle-TTL parking + revival via Agent Hub; agent:// history:// proc:// artifact URLs (85-113); IRC peer messaging; git-worktree isolation w/ merge; yield-tool contract w/ 3 reminders; soft request budget 200; depth limit 2; seance = consult past sessions (254-266); auto-parallel splitting judged by model (242-252).
9. **Models** — 60+ providers (README.md:31), 9 roles: default/smol/slow/plan/commit/vision/task/advisor/tiny (341); fallback chains; round-robin credentials; path-scoped models; per-call approval; judge model for TTSR/auto-parallel.
10. **Update** — omp.sh installer w/ SHA-256 check, brew/bun/nix/mise; shell completions generated from live metadata.
11. **Config** — ~/.omp/agent/config.yml (+ models.yml), YAML, path-scoped entries; much larger surface than pi (per-subsystem knobs for memory/compaction/task/ttsr/lsp).
12. **Error recovery** — pi's machinery + compaction method-order fallback; 413 payload-rejection guard (distinct from token-overflow); context promotion (upsize model before compacting); incomplete-output recovery capped at 3.
13. **Clever / notably bad** — Clever: **hashline edits** — read/grep results tag files with content-hash anchors `[path#TAG]`; edit addresses lines as `TAG:12` etc.; stale anchors are rejected and can be recovered via re-read (docs/tools/edit.md:30-74,163-175; crates/pi-edit ~9k lines); benchmark: edit success 6.7%→68.3% on Grok Code Fast (README.md:31-45). **TTSR** — regex/AST rules evaluated on the model's *stream* mid-token; on match: abort, inject rule reminder, retry (docs/ttsr-injection-lifecycle.md:96-156), optional judge-model rules (298-319). **Read summarization** — large reads return structural summaries instead of dumps (read-summary.ts) + supersede tracking. File writes routed through LSP willRenameFiles. Advisor model reviews subagent work (docs/advisor-watchdog.md). Bad: complexity explosion (5 compaction methods, 5 memory backends, 25 search providers, tts/computer/collab in core), config sprawl, several features assume cloud/beta provider endpoints.

## pi vs omp divergence — did the fork pay off?

- omp = pi's skeleton + (1) Rust native core for speed (grep/edit/shell in-process), (2) hashline-anchored editing, (3) LSP/DAP integration, (4) a full subagent/task system, (5) a memory subsystem, (6) a compaction toolbox, (7) TTSR stream rules, (8) massive provider/config surface.
- Paid off: edit reliability (measured 10x on weak models), token economy (summarized reads + elision + compaction cut output tokens ~61% per README), subagent fan-out with artifact URLs keeps parent transcripts small. These map to real agent failure modes (bad edits, context bloat, tool-dump flooding).
- Questionable: collab relay, browser/computer-use, TTS, IDA, 25 search providers — wide surface, niche demand; provider-native compaction betas couple the harness to vendor APIs; five compaction methods × five memory backends is a maintenance matrix pi deliberately avoids.
- Net: omp is "pi + a research agenda"; pi is the extractable minimal core. For August, omp is best read as a menu of *isolated* techniques, not an architecture to copy.

## Ideas worth stealing for August

1. **failToolCallsFromTruncatedMessage** (pi agent-loop.ts:488-513): when a length-stop truncates an assistant message, fail *all* tool calls in it instead of executing half-parsed calls. August's loop already has thinking-only rescue; add this invariant to the stream accumulator.
2. **declareToolChanges deltas** (pi agent-loop.ts:342-372): emit toolsAdded/toolsRemoved as a system message instead of re-rendering the whole prompt when the tool surface changes (August's plan-mode tool filtering). Preserves provider prompt cache.
3. **Per-realpath file-mutation queue** (pi file-mutation-queue.ts): serialize edit/write per file across parallel tool batches — August has dual-order parallel batches but needs the same-file write lock.
4. **Never-cut-tool-results compaction invariant + file-op ledger** (pi compaction.ts:60-114, docs/compaction.md): compact only at user-message boundaries; carry firstKeptEntryId and cumulative files-created/modified into the summary. Fits August's compact-in-place/rotate in brain.
5. **Superseded-read pruning + useless-result elision** (omp docs/compaction.md:548-549, read-supersede.ts): blank old tool outputs that newer reads supersede or that changed nothing — cache-aware, big token win for long coding sessions. Touches August's compaction prune step.
6. **Speculative/async compaction** (omp docs/compaction.md:532): start summarizing in a pre-threshold band; commit synchronously only when the threshold is actually crossed. Direct upgrade to August's pre-turn auto-compact latency.
7. **Recall-as-background + persisted memory context** (omp docs/memory.md): inject recalled memories once as a background block at turn 1 and keep it in the transcript (cache-stable), with secret redaction and lease/heartbeat consolidation. Fits August's one-markdown-store + FTS5 index without adding a vector store.
8. **TTSR-lite stream guard** (omp docs/ttsr-injection-lifecycle.md): cheap regex rules over streamed tool arguments (e.g. destructive shell patterns) that abort + re-inject a reminder before execution. August already flags tool-call narration post-hoc; this moves the check mid-stream, pre-execution — pairs with the approval gate.
9. **Freshness-token edits** (cheap hashline): have read_file return a short content hash/tag and require it in edit_file; reject stale edits with a re-read hint (omp docs/tools/edit.md:163-175 shows the recovery UX). Avoids porting the full Rust hashline grammar.
10. **Subagent artifact URLs + idle parking** (omp docs/tools/task.md:85-113, agent:// proc://): subagent outputs above a cap become a file + preview line addressable as agent://…; park finished workers and revive on demand. August's subagents currently cap output bytes; the URL scheme is the cleaner escape hatch.
11. **Project-trust gate** (pi docs/extensions.md project_trust): persist per-project trust (ask/always/never) granted before loading repo resources — matches August's `.aug/skills` projectSkills toggle and `.aug/hooks.json` per-workspace trust door.
12. **Session trees** (pi /tree /fork /clone + branch summaries): linear transcripts → a tree with labeled branches and auto-summaries on navigation; natural fit for August's workbench UI (state/ map + transcript store already exist).

## Anti-patterns to avoid

- **Knob explosion**: omp's per-subsystem config matrices (5 compaction methods, 5 memory backends, dozens of toggles) vs August's "absent = armed, 0 = off". Adopt techniques, not the configuration surface.
- **In-process extension execution with full user privileges** (pi): supply-chain hardening (pinning, ignore-scripts, min-release-age) helps but the execution model is still trust-all. August's repo-skills-load / hooks-exec split is the better shape.
- **Vendor-coupled core paths**: provider-native compaction betas (Anthropic compact-2026-09-04, OpenAI /responses/compact) inside the mainline compaction order — keep provider-specific tricks behind capability checks, as August already does for thinking payloads.
- **Feature dumping into the core**: tts, computer-use, 25 search providers, collab relays — each adds attack surface and maintenance for niche demand.
- **snapcompact bitmap imaging**: clever, but model-aware shapes + vision-dependence + eval-specific recall gains; too fragile as a default.
- **Trusting the model with no permission layer at all** (pi's stance): fine for a dev tool, wrong default for a product that runs on user machines — August's approval gates should stay.

## Not applicable to August (and why)

- Rust natives / N-API core (~80k lines): August is Python+TS; fork/exec or subprocess pools are fine at its scale.
- Bun runtime, bazel build: toolchain churn without product payoff.
- Browser relay, computer-use, TTS, IDA integration, collab relay: out of product scope (local-first workbench).
- 60-provider matrix + role system ×9: August is a gateway with user-pasted base URLs; keep the small provider set.
- Full hashline patch language + tree-sitter anchors: high value but a multi-week Rust/TS port; the freshness-token variant captures most of the safety win.
- mnemopi embeddings/graph store: conflicts with August's one-store memory rule; FTS5 + markdown already cover recall.
