# Harness study: openai/codex, block/goose, google-gemini/gemini-cli

Read-only static review for August (local-first AI gateway + agentic workbench).
All paths repo-relative. Claims are from files read directly; doc-only claims are marked (doc).

---

## 1. openai/codex (Rust workspace `codex-rs/` ~120 crates + `codex-cli/` TS + `sdk/`)

Coding agent CLI/desktop. Docs in `docs/` are mostly stubs pointing at developers.openai.com; source is the real spec.

1. **Startup flow** — `codex-rs/cli/src/main.rs` parses commands (exec, mcp, plugin, doctor, app…). TUI lives in `codex-rs/tui/src/` (`app.rs`, `chatwidget/`); a separate app-server family (`app-server*`, `app-server-protocol`) decouples core from IDE/desktop UIs. `codex-rs/codex-home/` resolves `$CODEX_HOME`.
2. **UI/UX patterns** — Ratatui TUI with chat widget + bottom pane (`tui/src/chatwidget.rs`, `tui/src/bottom_pane/`); approval prompts surface as protocol events (`protocol/src/approvals.rs`), so every UI shares one approval model.
3. **Memory model** — `codex-rs/memories/README.md`: two-phase pipeline. Phase 1 claims eligible rollouts from a state DB (idle/age/claim limits), extracts structured `raw_memory` + `rollout_summary` per thread via model calls with a concurrency cap, redacts secrets, stores stage-1 outputs with retry backoff. Phase 2 takes a global lock, ranks by `usage_count`/recency with `max_unused_days` pruning, syncs `raw_memories.md` + `rollout_summaries/` under a **git-baselined** `~/.codex/memories/.git`, writes `phase2_workspace_diff.md`, and runs a consolidation sub-agent (no approvals, no network, local writes only, collab disabled). Sub-agent sessions are excluded from the memory pipeline; parent-only writes.
4. **Skills** — `codex-rs/skills/src/`: SKILL.md frontmatter parsing (`parser.rs`, `metadata.rs`), embedded system skills installed to `$CODEX_HOME/skills/.system` behind a content-fingerprint marker (`lib.rs::install_system_skills`), explicit `@skill` mentions + implicit invocation detection (`selection.rs`, `invocation.rs`, `mentions.rs`), `SkillPolicy`/dependencies/tool deps (`model.rs`). Skills can require their own approval class (`skill_approval`).
5. **Tool + permission model** — `AskForApproval` = `UnlessTrusted | OnRequest | Granular(...) | Never` (`protocol/src/protocol.rs:1187`); `GranularApprovalConfig` splits sandbox-escalation, execpolicy-rule prompts, skill approval, `request_permissions`, and MCP elicitations into independent toggles. `execpolicy` crate (`execpolicy/src/policy.rs`, `rule.rs`) matches per-program prefix rules + network rules → Allow/Deny/Prompt, with case-canonical fallback matching.
6. **Sandboxing** — `codex-rs/sandboxing/src/`: Landlock + PID namespace (Linux), Seatbelt incl. a seatbelt daemon (macOS), Windows restricted-token + MXC sandbox, bubblewrap fallback (`bwrap.rs`); `SandboxMode` = read-only / workspace-write / danger-full-access (`protocol/src/config_types.rs:104`); `sandbox_integrity/` verifies sandbox contents; `violation.rs` records fs/network violations; `network-proxy` crate for proxied egress.
7. **Context management** — `core/src/compact.rs` (+ `compact_*` siblings): summarization with a token-capped user message (`COMPACT_USER_MESSAGE_MAX_TOKENS = 20_000`), PreCompact/PostCompact hooks, `AutoCompactionDisabled` for sub-threads, remote compaction v2, retained tool outputs; rollout-side compression in `rollout/src/compression.rs`.
8. **Subagent design** — `core/src/thread_spawn.rs`, `thread_manager/`; `agent-graph-store/src/types.rs` tracks parent→child spawn edges (`open`/`closed`); `agent-roles/` loads role configs from disk; `agent-message-board*` + `message-board-mcp` give agents a shared message board; `SubagentStart/Stop` hooks; `codex_delegate.rs` for delegation.
9. **Model/provider handling** — `model-provider`, `model-provider-info`, `models-manager` crates; ChatGPT-plan auth vs API key (`login/`, `chatgpt/`); `responses-api-proxy`, `aws-auth`/Bedrock, `ollama`, `lmstudio`; retry with `RetryAfter` in `core/src/responses_retry.rs`.
10. **Update mechanism** — install scripts (releases.openai.com with GitHub fallback) / npm / brew (README). `cli/src/doctor/updates.rs` diagnoses update health from cached version metadata + channel hints + bounded HTTP probes and "never executes package managers"; desktop uses appcast XML/JSON (Sparkle / Windows Store).
11. **Config/settings** — layered TOML in `config/src/config_layer_source.rs`: PackagedDefaults < Mdm < System < EnterpriseManaged < User(+profile) < Project(`.codex/`) < SessionFlags, each with numeric precedence; admin `requirements.toml` can force `allow_managed_hooks_only` (docs/config.md).
12. **Error recovery** — rollout resume via `InitialHistory`/`ResumedHistory` (`rollout/src/lib.rs`), state-DB job leases with retry backoff (memories), sandbox-denial heuristics (`sandboxing/src/denial.rs`), `doctor` command, model fallback for compaction (`compact_model_fallback.rs`).
13. **Clever / notably bad** — Clever: rollout JSONL with ordinals + `reverse_jsonl_scanner` + `seekable_reader`; a documented serde arbitrary-precision workaround kept at the persistence boundary (`rollout/src/lib.rs:44-76`); git-baselined memory workspace whose diff *is* the consolidation prompt; fingerprint-marked system-skill cache. Bad: `docs/sandbox.md`, `docs/execpolicy.md`, `docs/skills.md` are 3-line stubs to an external site — poor offline/open-source navigation; dual bazel+cargo build adds weight.

## 2. block/goose (Rust workspace, 15 crates + Electron desktop `ui/desktop` + `goose-sdk` uniffi)

General-purpose local agent (desktop + CLI + API), MCP-first, Linux Foundation project.

1. **Startup flow** — `crates/goose-cli/src/main.rs` dispatches commands; desktop (`ui/desktop`, Electron Forge) embeds/spawns the Rust agent; `goose acp` runs goose as an **ACP server over stdio** so Zed/JetBrains connect directly (documentation/docs/goose-architecture/goose-architecture.md).
2. **UI/UX patterns** — Desktop app + terminal CLI with themes/`GOOSE_CLI_SHOW_COST`/bell; "Action required" confirmations; recipes (`workflow_recipes/`) as reusable workflows; scheduler for task queues.
3. **Memory model** — memory is a built-in MCP extension; sessions persist and export to Markdown/HTML (`crates/goose/src/session/export_markdown.rs`, `export_html/`); context revision (below) is the main long-session memory strategy.
4. **Skills/plugins/extensions** — Skills: SKILL.md walk + built-ins (`crates/goose/src/skills/builtins/*.md`), global `~/.agents/skills` + project `<proj>/.agents/skills` (`skills/mod.rs:45-54`), frontmatter per agentskills.io spec with a free-form `metadata` bag, exposed to the model as a `SkillsClient` MCP extension; plugins with scopes (`crates/goose/src/plugins/`); extensions = MCP servers (70+ documented); custom distros (CUSTOM_DISTROS.md).
5. **Tool + permission model** — `GOOSE_MODE` = auto / approve / chat / smart_approve (docs/guides/config-files.md). Permission module (`crates/goose/src/permission/`): `permission_judge.rs` uses an **LLM-as-judge** tool (`platform__tool_by_tool_permission`) to classify requests as read-only, explicitly treating request IDs/args as untrusted data; `permission_store.rs` persists decisions in `permissions/tool_permissions.json` keyed by tool name + **blake3 hash of the tool context**, with expiry timestamps and atomic temp-file+rename writes. `goose-agent/src/tool_approval.rs` models decisions as `Allow | Deny{reason} | Ask{prompt}`.
6. **Sandboxing** — No OS-level sandbox in core; safety comes from permission gating + optional Docker runs. (Contrast with codex/gemini.)
7. **Context management** — `crates/goose-context-management/` is a standalone compaction library: `CompactionInput`/`CompactionOutput` traits, `summarize()` with a pluggable `CompactionModel` + `TokenEstimator`, `StructuredSummary` with file activity, `DEFAULT_COMPACTION_THRESHOLD = 0.8` (lib.rs:32). Runtime triggers: `GOOSE_AUTO_COMPACT_THRESHOLD` (0.8) and absolute `GOOSE_AUTO_COMPACT_TOKEN_LIMIT` (225000) — whichever hits first (docs/guides/config-files.md:68-69). Exported to Python/Kotlin via the SDK.
8. **Subagent design** — `goose-agent/src/subagent.rs`: `SubagentRunner` trait; parent scans messages for requested subagent session IDs, starts each with a `CancellationToken`, and consumes an `OperationStream<SubagentUpdate>` (`ToParent(Message)` / `Finished(outcome)`); roaming agents (`goose-roaming`, `commands/roam.rs`) run on remote/other machines.
9. **Model/provider handling** — `goose-providers/src/`: anthropic, openai, openai_compatible, openrouter, google, azure_foundry, databricks, snowflake, ollama, local_inference; **ACP agents as providers** (delegate to Claude Code/Codex); tool-shim for models without native tool calling; live/voice providers.
10. **Update mechanism** — `goose update` CLI with `--canary`/`--reconfigure` (docs/guides/updating-goose.md); desktop auto-update via Electron; `goose-download-manager` crate.
11. **Config/settings** — YAML family in one dir: `config.yaml` (provider/model/GOOSE_* keys), `permission.yaml`, `secrets.yaml` (file-based secret storage), `permissions/tool_permissions.json`, `prompts/` templates; env vars override for the process (docs/guides/config-files.md).
12. **Error recovery** — errors (invalid JSON, missing tool, execution failure) are returned to the model **as tool responses** so it can self-correct (docs/goose-architecture/error-handling.md); on interruption the state machine synthesizes error tool-responses for open tool calls (`goose-agent/src/machine.rs:74-88 interrupted_tool_responses`).
13. **Clever / notably bad** — Clever: the agent is a **state machine of Operation/Inference steps with effects** (`machine.rs`) — cancellable, resumable, wasm-compatible; permission store with context-hash + expiry; compaction as a reusable crate; **tool deferral** (`GOOSE_TOOL_DEFERRAL=lookup`: publish tool names up front, load schemas on demand via `enable_tools`) to save tokens. Bad: env-var-style `GOOSE_*` keys living inside YAML config (two naming systems); permission safety leans on a non-deterministic LLM judge; no OS sandbox.

## 3. google-gemini/gemini-cli (TS monorepo: `packages/cli`, `core`, `sdk`, `a2a-server`, `vscode-ide-companion`)

Enterprise Gemini Code Assist terminal agent; richest policy/confirmation architecture of the three.

1. **Startup flow** — `packages/cli/src/interactiveCli.tsx` (Ink UI) vs `nonInteractiveCli.ts`; settings + auth resolved at boot; Auto Memory extraction service starts during session boot (docs/cli/auto-memory.md).
2. **UI/UX patterns** — Ink/React terminal UI: `/settings` dialog, themes, vim mode, footer with sandbox status + model + context %, dynamic window-title status icons (Ready ◇ / Action Required ✋ / Working ✦), compact tool output (docs/cli/settings.md).
3. **Memory model** — GEMINI.md hierarchy for static context; **Auto Memory** (experimental, docs/cli/auto-memory.md): background task mines transcripts in `~/.gemini/tmp/<project>/chats/` (eligible = idle ≥3h, ≥10 user msgs), coordinates via lock + state files, drafts memory updates as **unified-diff .patch files** and reusable SKILL.md drafts into a project-local **review inbox**; it can never directly edit active memory files, settings, credentials, or GEMINI.md; patches are parsed, target-allowlisted, dry-run, and applied atomically only on user approval.
4. **Skills/extensions** — SKILL.md skills with an `activate_skill` tool (`core/src/tools/activate-skill.ts`, docs/cli/skills.md); extensions with their own docs (docs/extensions/) and a policy tier; MCP servers; TOML custom commands; ACP mode; a2a-server for agent-to-agent.
5. **Tool + permission model** — **Policy engine** (`core/src/policy/`): declarative TOML rule files (`policies/read-only.toml`, `write.toml`, `plan.toml`, `yolo.toml`, `non-interactive.toml`, `agents.toml`, `sandbox-default.toml`, `discovered.toml`, `conseca.toml`) with decisions `allow | deny | ask_user` and **tiered priorities**: Default 1.x < Extension 2.x < Workspace 3.x < User 4.x < Admin 5.x, plus dynamic settings-based rules at 4.1–4.95 (UI "always allow", excluded MCP servers, `--allowed-tools`/`--exclude-tools`, MCP trust=true). The **confirmation bus** (`core/src/confirmation-bus/types.ts`) decouples tools from the UI: `TOOL_CONFIRMATION_REQUEST/RESPONSE`, `TOOL_POLICY_REJECTION`, `ASK_USER_*`, `SUBAGENT_ACTIVITY`, with rich serializable details (diffs, sandbox_expansion) and a `forcedDecision` bypass. Approval modes: default / auto_edit / plan / yolo.
6. **Sandboxing** — `core/src/sandbox/` + docs/cli/sandbox.md: macOS Seatbelt profiles (`permissive-open` default, `permissive-proxied`, `restrictive-*`, `strict-*`), Docker/Podman containers, runsc, LXC; enabled via `-s` flag > `GEMINI_SANDBOX` env > `settings.json` `tools.sandbox`.
7. **Context management** — `core/src/context/`: a **graph-based ContextManager** (pristine master graph + active graph, working buffer, pipeline orchestrator, event bus, invariant checker, render cache, hysteresis on compaction triggers to prevent churn — `contextManager.ts:30-56`); `chatCompressionService.ts`, `contextCompressionService.ts`, `PreCompress` hook; token-caching support (docs/cli/token-caching.md).
8. **Subagent design** — docs/core/subagents.md: subagents are **exposed as tools** with their own system prompt, restricted toolset, and independent context loop; built-ins `codebase_investigator`, `cli_help`, `generalist` (inherits main toolset for heavy subtasks), `browser_agent`; `@name` syntax forces delegation; per-subagent overrides in settings (`agents.overrides.<name>.modelConfig/runConfig.maxTurns`).
9. **Model/provider handling** — Gemini API / Code Assist / Vertex; **model routing** with fallback on failure (`ModelAvailabilityService`, user consent or silent chain flash-lite→flash→pro — docs/cli/model-routing.md); experimental **local Gemma routing** via LiteRT-LM to keep routing decisions on-device (docs/core/local-model-routing.md); strategy composition in `core/src/routing/strategies/` (classifier, approvalMode, composite, fallback, override); plan-mode steering (Pro plans, Flash implements).
10. **Update mechanism** — npm channels: `preview` (Tue 23:59 UTC), `stable` (promotion of last week's preview), `nightly` (README); `general.enableAutoUpdate` setting.
11. **Config/settings** — `settings.json` layered user (`~/.gemini/`) < workspace (`.gemini/`) < system (`/etc/gemini-cli/`) < extensions; `/settings` dialog edits everything; policy TOMLs separate; hooks in settings (docs/hooks/index.md).
12. **Error recovery** — **Checkpointing** (docs/cli/checkpointing.md): before any file-modifying tool runs, snapshot project state into a **shadow git repo** `~/.gemini/history/<project_hash>` + save conversation + the tool call; `/restore` reverts files, restores history, and re-proposes the call. Plus model-routing fallback, `retryFetchErrors`, `maxAttempts` (≤10), session retention/cleanup.
13. **Clever / notably bad** — Clever: confirmation bus as a typed message protocol; TOML policy tiers; shadow-git checkpointing tied to tool approvals; auto-memory review inbox with patch allowlisting; hooks with a strict contract (stdout must be pure JSON — pollution defaults to "allow" with the junk as a system message; exit 0 = parse JSON, 2 = hard block with stderr as reason, other = warn — docs/hooks/index.md). Bad: confusing product matrix in README (not tuned for Gemini 4+, free tier moved to Antigravity CLI); experimental features that need a restart to toggle; 80+ settings is the opposite of minimalist.

## Ideas worth stealing for August

1. **Granular approval policy enum** — codex `protocol/src/protocol.rs:1187` `AskForApproval::Granular{sandbox_approval, rules, skill_approval, request_permissions, mcp_elicitations}`. August's 4 guard modes could gain per-category switches instead of one global knob, so "medium" can still auto-allow reads but ask for skills. Touches: backend guard/approval config, UI guard settings.
2. **Permission store with context-hash + expiry** — goose `crates/goose/src/permission/permission_store.rs`: persist "tool X with args-hash Y approved until T" in one JSON file, atomic temp+rename write. Fits August's local-first minimalism (no DB) and kills repeat prompts. Touches: backend tool-loop approval persistence.
3. **Declarative TOML policy with priority tiers** — gemini `packages/core/src/policy/policies/*.toml` + `policy-engine.ts`: allow/deny/ask rules, workspace < user < admin precedence. Maps directly onto August's guard modes + repo-trust story, and is auditable text, not code. Touches: guard config format, security docs.
4. **Confirmation bus** — gemini `core/src/confirmation-bus/types.ts`: typed request/response messages (with correlation IDs and rich details like diffs) between the tool executor and the UI. Natural fit for Tauri's backend↔frontend event bridge; keeps the loop UI-agnostic. Touches: backend turn loop, frontend approval pane.
5. **Checkpoint before destructive tools (shadow git)** — gemini docs/cli/checkpointing.md: snapshot + conversation + tool call before `write`/`replace`, one-command `/restore`. Cheap undo for a local-first app; can reuse the workspace's own git. Touches: backend file tools, security doors.
6. **Full lifecycle hook taxonomy** — codex `codex-rs/hooks/src/lib.rs:29-44` (PreModelRequest, PermissionRequest, PreCompact, SubagentStart/Stop, Interrupt…) and gemini docs/hooks/index.md. August already has `.aug/hooks.json` behind trust; adopting this event list (and gemini's exit-code contract: 0 = JSON decision, 2 = hard block, other = warn) makes hooks predictable. Touches: hooks module, security.md.
7. **Memory as review-inbox patches, not direct writes** — gemini docs/cli/auto-memory.md + codex `codex-rs/memories/README.md`: mine idle transcripts offline, draft MEMORY.md diffs into an inbox, apply atomically only on approval; skip sub-agent sessions entirely. Validates and extends August's parent-only memory door and markdown-fact store. Touches: memory importer/brain, skills learning pass.
8. **Tool-schema deferral** — goose config-files.md `GOOSE_TOOL_DEFERRAL=lookup`: advertise tool names, load schemas on demand via an `enable_tools` call. Directly reduces August's per-turn token budget with many MCP tools installed. Touches: tool registry, budgeted loop.
9. **Compaction trigger = min(% threshold, absolute token cap)** — goose `goose-context-management/src/lib.rs` (0.8 default) + `GOOSE_AUTO_COMPACT_TOKEN_LIMIT` (225k). Simple, predictable rule for August's context manager; keep summary + recent turns, run pre/post-compact hooks. Touches: backend context management.
10. **System skills cache with fingerprint marker** — codex `codex-rs/skills/src/lib.rs::install_system_skills`: embed bundled skills, install to a cache dir, skip work when a content-hash marker matches. Upgrade-safe way to ship August's `skills/` packs. Touches: skills loading, desktop update flow.
11. **Doctor-style update health check** — codex `codex-rs/cli/src/doctor/updates.rs`: diagnose install channel + latest version with bounded probes, never running package managers. Complements August's silent in-place update with a visible "am I current?" check. Touches: update flow, settings/about page.
12. **Interrupt-safe tool responses** — goose `goose-agent/src/machine.rs:74-88`: on cancel/interrupt, synthesize error tool-responses for every open tool call so a resumed session sees a consistent history. Touches: August turn loop cancellation path.

## Anti-patterns to avoid

- **Env-var-style keys inside YAML config** (goose `config.yaml` full of `GOOSE_*`) — two naming systems for one thing; August should keep one config vocabulary.
- **LLM-as-judge as the primary permission gate** (goose `permission_judge.rs`) — non-deterministic and prompt-injectable; fine as an advisory read-only classifier, never as the door. August's hardline credential doors should stay rule-based.
- **Docs as external stubs** (codex `docs/sandbox.md`, `docs/skills.md`) — 3-line pointers to a website; bad for offline/local-first introspection. Keep real docs in-repo.
- **80+ settings with dialog-driven discovery** (gemini settings.md) — discovery bloat; August's minimalist UI should expose few knobs with sane layering.
- **Experimental features requiring restart + buried flags** (gemini autoMemory) — friction and confusion; gate behind clear toggles that apply immediately where possible.
- **Non-atomic state writes** — all three persist decisions/state; only goose uses temp-file+rename. August should write state files atomically (it mostly does for memory).
- **Subagents with memory-write or approval powers** — codex explicitly excludes sub-agent sessions from the memory pipeline; keep August's "sub-agents read and recall, never write" invariant.

## Not applicable to August (and why)

- **OS-level sandboxing (Landlock/Seatbelt/MXC/docker/runsc)** — codex/gemini invest heavily because they run arbitrary model-generated shell on user machines. August's threat model centers on credential doors + path gates in a Tauri app; adopting a full sandbox kernel is out of scope now (worth revisiting if August ever executes untrusted code).
- **Enterprise config layers (MDM, `requirements.toml`, enterprise cloud bundles, admin policies)** — codex `config_layer_source.rs`, gemini policy tier 5.x. Single-user local-first product; keep user < project layering only.
- **Cloud task queues / roaming agents / a2a-server / live voice** — codex `cloud-tasks*`, goose `goose-roaming`, gemini `a2a-server`, voice crates. Out of scope for a local workbench.
- **Bazel dual-build, monorepo SDK bindings (uniffi Python/Kotlin)** — build/packaging machinery irrelevant to August's npm + FastAPI + Tauri stack.
- **IDE/editor integration via ACP server** — goose/gemini/codex all speak ACP for editors; August's product surface is its own desktop app, so this is optional future interop, not core.
- **Shadow-git checkpointing at full git-repo fidelity** — the *idea* is stolen above, but gemini's separate history repo + re-proposal flow is more machinery than August needs initially.
